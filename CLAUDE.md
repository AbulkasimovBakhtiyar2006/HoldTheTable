# CLAUDE.md — HOLD THE TABLE / 60-MINUTE BANZAI MODE

## Приказ

Ты — ведущий инженер и координатор параллельных агентов. Прочитай README.md и СРАЗУ реализуй HOLD THE TABLE. Пользователь просит не размеренную разработку, а «камикадзе-атаку» на техническую задачу: 60 минут максимального исполнения. Это метафора рабочего темпа. Меньше обсуждения, больше проверенных файлов и рабочих сборок.

Не заканчивай ответ планом. Не предлагай пользователю самому написать код. Не спрашивай разрешение на обычные локальные изменения, генерацию сцены, сборку, исправления и установку этой игры на подтверждённый Quest. Не меняй устройство наугад и не трогай чужие приложения/данные.

## Новое обязательное требование: AR-империя

Сначала прочитай раздел README «ОБЯЗАТЕЛЬНОЕ ОБНОВЛЕНИЕ: AR-ИМПЕРИЯ И СВИТОК». Это текущая постановка пользователя и обязательная часть реализации с приоритетом над старым автоматическим castle-on-table стартом.

Реальная комната остаётся видимой через passthrough. Рядом с игроком висит красивый переносимый императорский свиток: poke-выбор цивилизации, собственное имя через hand keyboard, выбор цвета знамени и рисование эмблемы пальцем. Из свитка игрок получает первую ратушу и размещает её на подходящей поверхности в любом выбранном месте комнаты. После этого строит от неё поселение; возле ратуши развевается знамя с его рисунком. Пример имени — Heavenly Kingdom.

Не заменяй рисунок только готовыми иконками, ввод имени только пресетом, а развевающееся знамя статичной картинкой. Не ограничивай AR одним заранее выбранным столом. Свиток — world-space объект рядом с игроком, боевой HUD остаётся wrist-attached. До подтверждения основания не запускаются волны/доход/countdown. Этот scope включается в текущий спринт; не выноси его в будущие планы.

Распредели дополнения между существующими агентами без конфликтов файлов:

- A: поверхности всей комнаты, EmpireFoundationController, выдача и ближнее/дальнее размещение ратуши, valid/invalid ghost.
- B: ратуша как keep, архитектурные варианты выбранной цивилизации, соответствующая геометрия построек.
- C: CivilizationDefinition/Profile, SettlementBuildArea, состояния setup/placement/combat, локальное сохранение оформления, restart с сохранением профиля и New Empire.
- D: ImperialScroll, CivilizationSelector, HandPokeKeyboard, EmblemDrawingCanvas, BannerCustomizer, BannerRenderer и все новые UI-строки.
- При доступном дополнительном слоте передай отдельному агенту Emblem & Banner исключительное владение EmblemDrawingCanvas, BannerCustomizer и BannerRenderer; иначе D выполняет их сам. Не создавай двух владельцев одних файлов.

В Contracts.md сразу согласуй CivilizationProfile (id/name/colors/emblem), событие подтверждённого основания и API зоны строительства. C владеет данными и состояниями, A сообщает о подтверждённом размещении, D меняет профиль через согласованный API и использует его для знамени. Лидер подключает всё в сцене и Validator.

Дополнения к расписанию: гейт 2 включает свиток/создание цивилизации/размещение ратуши, гейт 4 — расширение поселения, гейт 7 — оформление свитка/анимацию знамени, гейт 8 — тот же полный сценарий на fallback. Добавь acceptance tests из README в QA_REPORT и новый сценарий в submission/shotlist. Не объявляй готовность при отсутствии этих функций.

## Запрет на жалобы

Запрещены «это слишком сложно», «за час невозможно», «давайте урежем scope», «предлагаю сначала MVP», длинные оправдания, повторение требований и отчёты вместо работы. При трудности немедленно делай грубую, но настоящую реализацию того же поведения.

Разрешены и обязательны точные сведения об ошибке, неподтверждённой проверке и необходимом физическом действии пользователя. Запрет жаловаться НЕ разрешает скрывать сбой, выдумывать APK, FPS, успешное тестирование или наличие функции. TODO, пустой метод и кнопка без действия не считаются реализацией.

## Первые 3 минуты

1. Зафиксируй T0, deadline = T0 + 60 минут. Используй реальное прошедшее время. Читай README.md как полную спецификацию, сохраняй весь scope.
2. Найди фактический открытый Unity project root по запущенному процессу / доступной интеграции редактора; проверь ProjectVersion.txt, manifest, packages-lock и локальные инструкции. Эта папка может быть лишь папкой задания. Не создавай вторую копию проекта без необходимости.
3. Проверь установленные Editor, Android SDK/NDK/JDK, доступный Unity bridge и `metavr device list`. Сообщение пользователя о подключении устройства — основание проверить, а не основание выдумать serial.
4. Используй установленный совместимый SDK. Сигнатуры бери из PackageCache/исходников и официальных Meta docs через metavr. Не трать время на обновление исправного toolchain.
5. Запусти независимых агентов сразу после обнаружения проекта. Пока они работают, лично веди критический путь XR → компиляция → минимальный APK.

## Мультиагенты: обязательное параллельное исполнение

Если доступен механизм subagents/tasks, используй его немедленно. Лидер тоже пишет и интегрирует код, а не только ждёт. Начальный состав — лидер плюс до четырёх рабочих в пределах реального лимита среды. При меньшем лимите объединяй роли; при большем добавляй отдельного тестировщика/редактора документации. Не выдумывай агентов и не создавай бесконечное дерево.

| Владелец | Работа | Собственные файлы |
| --- | --- | --- |
| Лидер / Integrator | SDK, XR, Android settings, сцена, компиляция, APK, устройство | Packages, ProjectSettings, Scenes, Assets/Scripts/Editor, Assets/Editor/BuildScript.cs |
| Agent A / Table & Hands | MRUK, контур поверхности, fallback, anchors, grab/place, валидность ghost | TableAnchorBootstrap, FallbackTable, TraySlot, placement/hand adapters |
| Agent B / Combat | Keep/health, Catmull-Rom, separation, wall/tower/barricade, ram | Health, SplinePath, UnitDef, PlacedUnit, MonsterUnit |
| Agent C / Loop & Economy | Тимбер, 3 waves, win/lose/restart, score, upgrades | GameDirector, WaveSpawner, ScoreKeeper, QuartermasterAgent |
| Agent D / UX & Ability | Wrist HUD, cards/restart poke, shockwave, VFX, procedural audio | Assets/Scripts/UI, ShockwaveAbility, audio/VFX, Strings.cs |

Каждому агенту передай: абсолютный project root, README.md, его список файлов, интерфейсы, точный deadline, требование настоящей реализации и команды проверок. Дай задание «внести код в свои файлы», не «изучить и предложить». Подзадачи могут стартовать параллельно, но интеграционные гейты проходят в порядке README.

Зафиксируй в первые минуты краткий `Contracts.md`: namespace, типы событий, параметры публичных методов, владелец каждого shared type. Минимальные связи: ITableSurface (pose/bounds/validity/edge points), Health (damage/death), UnitDef (cost/HP/type), GameDirector (phase/placement/restart), upgrade modifiers, hand sample adapter. Все изменения контракта идут через лидера. Один владелец Strings.cs; остальные передают ему список ключей. Не давай нескольким агентам одновременно менять manifest, сцену, один .cs или .meta.

Не блокируй всех длинным проектированием интерфейсов: 10–20 строк согласованных контрактов достаточно для старта. Межагентские сообщения: готовый API, изменённые файлы, конкретная ошибка, результат проверки. Проверяй интеграцию каждые 5–8 минут. Если агенты работают в отдельных checkout, переносит изменения только лидер; если в общем каталоге, не cherry-pick уже видимые изменения.

Если subagents недоступны, сообщи это одной короткой строкой и веди те же рабочие потоки последовательно. Не трать спринт на установку оркестратора.

## Временной бюджет и последовательность гейтов

Это ориентиры для управления критическим путём, а не обещание, что сборщик закончит за фиксированное время. Запускай длительные импорты и builds как можно раньше, занимай ожидание независимой работой.

| 03–12 | Гейт 1: packages + XR/Android/IL2CPP + rig; ноль compile errors; минимальный APK |

Сдвиг времени не разрешает удалить функцию. На T+60 сохрани результат и кратко укажи фактическое состояние; если обязательная сборка/проверка ещё идёт, продолжай до её результата и честно укажи превышение часа.

## Правила интеграции Unity

- Генерируй сцену, prefabs, материалы, hand pose assets и wiring кодом. Повторный запуск SceneBuilder не должен плодить дубликаты или ломать ссылки.
- Единственный public static BuildScript.BuildApk находится в Assets/Editor/BuildScript.cs. SceneBuilder и Validator — в Assets/Scripts/Editor. Никаких двух классов BuildScript.
- Unity уже может держать проект открытым. Не запускай второй Editor на том же projectPath и не удаляй lock-файлы. Используй доступный bridge/Editor entry point для сборки; batchmode — только когда проект свободен. Не закрывай редактор с несохранённой работой.
- Поддержи команду `Unity -quit -batchmode -projectPath . -executeMethod BuildScript.BuildApk -logFile build.log`, запущенную из настоящего корня проекта; используй обнаруженный путь к Unity executable.
- Только лидер меняет ProjectSettings, manifest, shared scene и запускает Unity builds. Рабочие агенты не запускают конкурирующие builds/imports.
- Каждый компонент должен быть подключён к реально используемой сцене. Наличие класса без wiring не считается функцией.
- Runtime полностью offline; Quartermaster — локальная логика по статистике построек. Никакого cloud LLM.
- Все видимые игроку английские строки в центральном Strings.cs, включая UI, NPC, ошибки и upgrade descriptions. Технические ключи API, пути и editor diagnostics не являются игровыми строками.
- Контроллеры не нужны ни в одном пользовательском шаге, включая restart. Нужны настоящие Meta ISDK grab/poke/ray interactions, а не только имитация мышью в Editor.
- Доверяй типам установленного SDK, не случайному коду из памяти. Требуемый HandPose ScriptableObject и rig wiring должны соответствовать фактической версии; не маскируй отсутствие типа фиктивным одноимённым классом.
- Общий ITableSurface для MRUK/fallback, один gameplay loop. Reacquisition не должно дублировать стол/keep или сбрасывать игру.
- Restart сбрасывает monsters, structures, timber, wave timers, upgrades, score, keep HP и два заряда; подписки и корутины не накапливаются.
- Pooling для monsters/projectiles/VFX, shared materials, без LINQ/Find/GetComponent в горячем Update, без realtime shadows/postprocess/reflection probes. Сначала измеряй, затем исправляй выявленную нагрузку.
- Не удаляй существующий пользовательский код ради скорости; сохраняй исходную историю и незакоммиченные изменения. Не публикуй заявку/релиз и не выдумывай сведения о лицензиях.

## Если застрял

После двух минут без прогресса выдай ровно одну содержательную строку:
`BLOCKED | <что + доказательство> | A: <быстрый рабочий обход> | B: <второй вариант> | choosing A`

Сразу исполни A, сохраняя требуемое поведение. Если это внешняя необходимость (USB authorization, room scan, действие в шлеме), запроси одно точное действие и продолжай доступную независимую работу. Не считай отсутствие ответа подтверждением. Не возвращайся к одной нерабочей попытке без новых данных.

## Доказательства готовности

Веди компактный QA_REPORT.md: проверка → PASS / FAIL / NOT RUN → путь к логу/измерению и краткий результат. Проверяй:

- чистую компиляцию, успешный exit/result сборки, существование и размер APK;
- install и launch на обнаруженном Quest, отсутствие crash/exception/missing reference в снятом runtime log;
- hands-only placement, все unit types, timber, 3 waves/ram, win и loss, poke restart;
- реальную MRUK поверхность и forced fallback до EndScreen отдельно;
- shockwave gesture, 2 charges, push/damage, upgrade modifiers, auto-skip через 6 секунд;
- 30 активных units и устойчивый минимум 60 fps на устройстве: запиши длительность, инструмент, frame timing и падения; Editor FPS не подтверждает Quest FPS;
- Validator без пропусков обязательных компонентов/references и четыре непустых документа из README.

Automated smoke test полезен, но не выдавай его за физическое hands-only тестирование. Если проверка невозможна без пользователя, записывай NOT RUN. Не объявляй DONE, если definition of done не выполнен.
